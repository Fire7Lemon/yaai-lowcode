> **生成时间**：2026-05-25（接 [成员4最新版代码扫描与对齐诊断.md](./成员4最新版代码扫描与对齐诊断.md)）

## 1. 总原则

1. **成员 4 已有的，成员 3 尽量适配**（保持低代码数据贴近 YAAI 现有路由 / 组件 / store / API 形态）。
2. **成员 4 没有的，不强行改后台数据绕过**；而是 **生成明确 MD 指导成员 4 实现**（见 [成员4向低代码适配实现指南.md](./成员4向低代码适配实现指南.md)）。
3. **成员 3 职责**：输出稳定的低代码数据 — 菜单、页面、版本、平铺节点树、组件定义、数据绑定；保持契约口径不动摇。
4. **成员 4 职责**：实现前台动态渲染运行时 — `node-tree` API、平铺 → 树、`NodeRenderer`、`component-map`、`UnknownComponent`、`RichTextBlock` 与 `DynamicPage` 改造。
5. **后端职责**：修复 `publish` 等正式发布链路；联调期 `currentVersionId` 临时绑定仅作过渡。
6. **不依赖** `version.status === 'published'` 判断展示；以 `page.currentVersionId` 能拉到 `node-tree` 为准（联调约定，见 §7、§10）。

## 5. 路由适配决策

> 以 **YAAI 现有路由形态为基准**，成员 3 **不改 `pageType` / `path`**（除非成员 4 明确表示不修改前台路由规则）。

| `path` | YAAI 当前状态 | 成员 3 `page.path` | 决策 |
|--------|---------------|--------------------|------|
| `/` | ✅ 已动态注册（`createBuiltinModuleRoute` 命中 `code='home'`） → `views/home/Index.vue` | `page 7`：`path='/'`、`code='home'`、`portal` | **保持不变**；P2 阶段可由 `DynamicPage` 接管渲染 308 |
| `/news` | ❌ **当前无路由**（静态已删、`shouldRegisterDynamicRoute` 排除 portal） | `page 8`：`path='/news'`、`portal`、`currentVersionId=309` | **成员 4 改 `shouldRegisterDynamicRoute`**；成员 3 **不改** `pageType` |
| `/services` | ✅ 静态路由 → `views/services/Index.vue` | `page 9`：`path='/services'`、`portal`、`currentVersionId=310` | **保持不变**；联调期由静态视图兜底，**不与 DynamicPage 冲突**（静态优先级高于动态注册） |
| `/conference` | ✅ 静态路由 → `views/conference/Index.vue`（含 4 子路由） | `page 10`：`path='/conference'`、`portal`、`currentVersionId=311` | **保持不变**；同上 |
| `/about/introduction` | ❌ **当前无路由**（同 `/news`） | `page 11`：`path='/about/introduction'`、`portal`、`currentVersionId=312` | **成员 4 改 `shouldRegisterDynamicRoute`**；成员 3 **不改** `pageType` |

### 5.1 特别说明

- **首选**：成员 4 修改 `shouldRegisterDynamicRoute`，当 `pageType='portal'` 且 `path` 不在静态路由集合（`/services`、`/conference`、`/login`、`/user`、`/apply` 前缀、`/content` 前缀等）内时返回 `true`，让这些 path 落到 `DynamicPage`。
- **不推荐**：成员 3 改 `pageType` 来绕过 — 这等于"为了避免成员 4 改 3 行代码而修改后台数据语义"，违反本轮总原则 §1.2。
- **路由优先级**：Vue Router 中静态路由先于动态 `addRoute` 注册，因此 `/services`、`/conference` 永远命中静态视图，DynamicPage 注册不会冲突；可放心放开 portal 注册。

## 7. 数据格式适配决策

### 7.1 成员 3 保持

- 响应统一 **camelCase**；envelope `{code, success, message, data}`。
- `propsJson` / `styleJson` / `layoutJson` / `eventJson` / `visibleRuleJson` 始终为 **`string | null`**（**不**改成 object）。
- `node-tree` 始终为 **flat `nodes` 数组**，承载 `parentId / slotName / sortOrder`。
- `componentKey` 仅使用 **白名单 10 键**；不引入历史别名或非白名单键。
- 父子关系仅通过 **`parentId`** 表达；不引入 `children` 嵌套。
- 列表分页字段保持现状：`pages → records`、`menus → items`（成员 4 各自 store 已兼容，**不在本轮统一**）。

### 7.2 成员 4 负责

- **envelope 处理**：沿用 `utils/request.ts` 拦截器（已实现）。
- **`records` / `items` 差异兼容**：在各自 store 中已处理。
- **`propsJson` JSON.parse**：实现 `safeJsonParse(raw, fallback={})`，try/catch 兜底。
- **flat nodes → tree**：实现 `buildNodeTree`（按 `parentId` / `slotName` / `sortOrder`）。
- **`UnknownComponent` 兜底**：未知 `componentKey` 渲染兜底组件，不抛错。
- **节点级容错**：单节点渲染/解析失败不能拖垮整页（建议 `<Suspense>` 或在 NodeRenderer 内 `try/catch`）。
