## 1. 背景

- 成员 3 已按 **YAAI 现有结构**（5 个路由路径、8 个首页 section、`fetchPages`/`fetchMenus` 等）重建低代码数据，**菜单 / 页面 / 版本 / 节点树 / 组件定义 / 数据绑定** 已就绪。
- 当前 5 页 `currentVersionId` 已绑定（**308～312**），首页 308 已含 9 节点、栏目页 309～312 各含 `page_container + rich_text` 2 节点（见 [交接清单](./成员4前台联调数据交接清单.md) §3、§5、§6）。
- YAAI 已具备 `menus`/`pages` 拉取与动态路由注册骨架（`sitePagesStore.registerSiteRoutes` + `createBuiltinModuleRoute`），**但缺少 `node-tree` 渲染层**：`DynamicPage.vue` 仅占位，`NodeRenderer` / `component-map` / `UnknownComponent` / `RichTextBlock` / `buildNodeTree` / `public-node-tree` API / `lowcode` 类型全部缺失。
- 本指南列出成员 4 在 YAAI 内 **必须新增的最小集合**，让低代码运行时闭环。

## 2. 不需要成员 4 改的部分

- **不需要**改后台数据（page.path / pageType / component_key / propsJson / data_binding 等均不动）。

- **不需要**新增 `page-by-path` 接口（前台用 `fetchPages` 全量 + 本地 path 索引已足够）。
- **不需要**等后端修 `publish` 才开始；联调期以 `currentVersionId` 能拉到 `node-tree` 为准。
- **不需要**改 `utils/request.ts`（envelope 处理已生效；camelCase 与后端一致）。
- **不需要**改 `sitePagesStore` / `siteMenusStore` 的 `ensureLoaded`（已正确消费 `data.records` / `data.items`）。

## 3. 成员 4 必须新增的文件

> 建议路径（仅供参考，可按 YAAI 命名习惯微调）。

### 3.1 `src/api/public-node-tree.ts`

**职责**：封装 `GET /page-versions/{versionId}/node-tree`。

- 入参：`versionId: number`
- 出参：`Promise<Result<PageNodeTreeResult>>`
- 复用 `@/utils/request`（已自动解 envelope）
- **不**做字段映射，把响应原样返回；映射在 store / 渲染层做

签名建议：

```ts
import request from '@/utils/request'
import type { Result } from '@/types/result'
import type { PageNodeTreeResult } from '@/types/lowcode'

export function fetchPageNodeTree(
  versionId: number
): Promise<Result<PageNodeTreeResult>> {
  return request.get(`/page-versions/${versionId}/node-tree`)
}
```

### 3.2 `src/types/lowcode.ts`

**职责**：定义低代码节点/版本/树类型，避免 `any` 在渲染层蔓延。

关键点：

- **响应内层字段全部 camelCase**（与 YAAI 现有 `SitePage` / `SiteMenu` 类型一致）。
- **`propsJson` / `styleJson` / `layoutJson` / `eventJson` / `visibleRuleJson`** 全部为 **`string | null`**（**勿** 用 `Record<string, unknown>`）。
- **`data.page_version`** 在 envelope 内键名 **snake_case**，但其内部字段仍 camelCase（详见 [接口字段差异记录.md](../01_设计基线/接口字段差异记录.md) §`page-version — node-tree`）。

类型骨架：

```ts
export interface PageNode {
  id: number
  pageVersionId: number
  parentId: number | null
  nodeType: 'container' | 'component' | string
  componentKey: string | null
  nodeName?: string | null
  slotName: string | null
  sortOrder: number | null
  dataBindingId: number | null
  propsJson: string | null
  styleJson: string | null
  layoutJson: string | null
  eventJson: string | null
  visibleRuleJson: string | null
  status: boolean
}

export interface PageVersionMeta {
  id: number
  pageId: number
  versionNo: number | null
  status: 'draft' | 'published' | string
}

export interface PageNodeTreeResult {
  nodes: PageNode[]
  page_version?: PageVersionMeta
}

export interface PageNodeTreeNode extends PageNode {
  children: PageNodeTreeNode[]
}
```

### 3.3 `src/utils/buildNodeTree.ts`

**职责**：把后端平铺 `PageNode[]` 转为带 `children` 的递归树。

规则：

- `parentId == null` 为根节点；正常情况下应仅 1 个根。
- 同一 `parentId` 下的子节点按 `sortOrder` 升序（`null` 视为 0）。
- 可选：按 `slotName` 分桶（首阶段统一 `main`，无需细化）。
- 输入 `PageNode[]`，输出 `PageNodeTreeNode[]`（一般取 `[0]` 作为根传给 `NodeRenderer`）。
- **不**抛错；遇孤儿节点（parentId 在数组中找不到）应跳过并 `console.warn`，避免破坏整体树。

### 3.4 `src/components/lowcode/NodeRenderer.vue`

**职责**：根据 `PageNodeTreeNode` 递归渲染。

要点：

- props：`node: PageNodeTreeNode`
- 在 `setup` 内 `safeJsonParse(node.propsJson, {})` / `safeJsonParse(node.styleJson, {})` / `safeJsonParse(node.layoutJson, {})`
- 通过 `component-map[node.componentKey]` 查目标组件；查不到 → `UnknownComponent`
- `<component :is="target" v-bind="props" :style="style">` 渲染当前节点
- 节点为 **容器**（`nodeType='container'` 或 `componentKey='page_container'`）时，**递归**渲染 `node.children`（默认放入目标组件的默认 slot 或 `slot="main"`）
- 节点为 **业务组件**（叶子）时，**不递归子节点**（首阶段不嵌入子节点）
- 用 `try/catch` 包住单节点渲染；失败渲染 `UnknownComponent` 并 `console.warn`，不抛到上层

### 3.5 `src/components/lowcode/component-map.ts`

**职责**：维护 `componentKey → Vue 组件` 的唯一映射表。

- 仅维护白名单 10 键（见 §5）
- `getComponentByKey(key)`：找不到时返回 `UnknownComponent`（**不** 返回 undefined）
- 用动态 `defineAsyncComponent(() => import('@/views/home/sections/HomeCarousel.vue'))` 等懒加载，避免首屏全量打包

### 3.6 `src/components/lowcode/UnknownComponent.vue`

**职责**：兜底显示未知组件，不抛错。

- props：`componentKey?: string`、`nodeName?: string`
- 显示一段灰色提示文案，如：`[未知组件: {{ componentKey }} ({{ nodeName }})]`
- **不**使用 `throw`、`console.error`；仅 `console.warn`

### 3.7 `src/components/lowcode/RichTextBlock.vue`

**职责**：渲染 `rich_text` 占位富文本。

- props：`title?: string`、`content?: string`
- 渲染：可选标题 + 段落 `content`（纯文本优先；如需 HTML 渲染请配合 sanitize 库后再 `v-html`）
- 风格可参考 `components/about/AboutStaticArticle.vue`，但不强制复用其结构
- 309～312 均使用此组件

### 3.8（可选）`src/components/lowcode/LowcodeContainer.vue`

**职责**：实现 `page_container` 布局壳。

- props：`propsJson` 中的 `title`、`layoutJson` 中的 `maxWidth` / `center` 等
- 渲染：`<div class="lowcode-container" :style="layoutStyle"><slot/></div>`
- 也可在 NodeRenderer 内联实现，不必单独建文件；按 YAAI 风格择优

## 4. DynamicPage 改造逻辑

> 文件：`src/views/cms/DynamicPage.vue`（当前为占位）。

伪流程：

1. 由 `route.meta.pageId` 或 `route.path` 在 `sitePagesStore` 中定位 `page`。
2. 读取 `page.currentVersionId`；若为 `null` → 渲染兜底"该页面暂无内容"。
3. 调用 `fetchPageNodeTree(currentVersionId)`；失败 → 渲染兜底错误页（含 page.path 与重试按钮，**不**抛错）。
4. 响应成功 → `buildNodeTree(data.nodes)` → 取根节点。
5. 渲染 `<NodeRenderer :node="root" />`。
6. 整个过程在 `<Suspense>` 或显式 `loading/error` 状态机内进行，避免空白屏。

错误边界建议：

- 网络失败：显示"加载失败，请重试"
- `nodes` 为空数组：显示"页面内容为空"
- 没有根节点（多根 / 孤儿）：以 `console.warn` 记录，仍尝试渲染第一个根节点

## 6. JSON 解析约定

- `propsJson` / `styleJson` / `layoutJson` / `eventJson` / `visibleRuleJson` 均为 **字符串或 `null`**。
- 推荐 `safeJsonParse(raw, fallback={})`：

```ts
export function safeJsonParse<T = Record<string, unknown>>(
  raw: string | null | undefined,
  fallback: T
): T {
  if (raw == null || raw === '') return fallback
  try {
    return JSON.parse(raw) as T
  } catch (err) {
    console.warn('[lowcode] safeJsonParse failed:', raw, err)
    return fallback
  }
}
```

- **解析失败不能让页面崩溃**；返回 `fallback`（默认 `{}`）。
- **不**对 `null` 报错；视为空对象。
- **不**在 API 层 `JSON.parse`（API 层保持字符串语义，与契约一致）。

## 7. 联调临时约定

- **当前 `version.status = 'draft'`**（308～312 均为 draft）。
- **`POST /page-versions/{id}/publish`** 仍 `SYSTEM_ERROR`（见 [后端待修复清单.md](../04_后端修复/后端待修复清单.md) §10）。
- **联调阶段**：以 **`page.currentVersionId` 有值且能拉到 `node-tree`** 为准；**不**使用 `version.status === 'published'` 判断是否展示。
- **不**调用 `POST /page-versions/{id}/publish`（前台只读）。
- **正式上线前**：等后端修复 publish 后，再切换为 `published` 语义；同步撤销 `PUT /pages` 临时写 `currentVersionId` 的过渡方案。
- 路由优先级：YAAI Vue Router 静态路由先于 `registerSiteRoutes` 动态注册命中；`/services`、`/conference` 走静态视图，`DynamicPage` 不会与之冲突，可放心放开 portal 注册。
