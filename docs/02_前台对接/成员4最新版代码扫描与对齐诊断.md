### 2.2 路由结构

- **静态路由**（`src/router/index.ts`，硬编码）：
  - `/services` → `views/services/Index.vue`

  启动时按 `GET /pages` 结果，调用 `createBuiltinModuleRoute(page)` 与 `shouldRegisterDynamicRoute(page)`：
  - `code === 'home'` 或 `(pageType === 'portal' && base === '/')` → `views/home/Index.vue`（静态首页 sections）

  - `pageType in {portal, channel, single}` 或 `code='home'` → **`shouldRegisterDynamicRoute` 返回 false**，**不注册** DynamicPage

## 3. YAAI 路由与后台 page.path 对齐情况

### 3.1 5 个后台 `page.path` 落地路径检查

| `page.path` | pageType | code | YAAI 当前承接 | 状态 |
|-------------|----------|------|---------------|------|
| `/` | `portal` | `home` | `views/home/Index.vue`（**动态注册**，`createBuiltinModuleRoute` 命中 `code === 'home'`） | ✅ 可访问 |
| `/news` | `portal` | `news` | **无**（静态路由已删，`shouldRegisterDynamicRoute` 对 `portal` 返回 false） | ❌ **当前 404** |
| `/services` | `portal` | `services` | `views/services/Index.vue`（**静态路由**） | ✅ 可访问，但与动态注册逻辑无关 |
| `/conference` | `portal` | `conference` | `views/conference/Index.vue`（**静态路由**，含 4 子路由） | ✅ 可访问 |
| `/about/introduction` | `portal` | `about_introduction` | **无**（同 `/news`） | ❌ **当前 404** |

### 3.2 关键阻塞：portal 类型未注册动态路由

`src/utils/sitePageNav.ts` 中的 `shouldRegisterDynamicRoute`：

```5:21:YAAI/src/utils/sitePageNav.ts
export function shouldRegisterDynamicRoute(page: SitePage): boolean {
  if (!page.status) return false
  if (BUILTIN_MODULE_CODES.has(page.code)) return false
  if (page.pageType === 'channel' || page.pageType === 'single') return false
  if (page.pageType === 'portal') return false
  return true
}
```

- 仅 `pageType='custom'`（或其他非 portal/channel/single 的类型）才会注册到 `DynamicPage`。
- 后台 5 页 **全部** `pageType='portal'`，因此除了 `code='home'` 走 `createBuiltinModuleRoute` 命中之外，**其余 portal 页都不会有动态路由**。
- `/services`、`/conference` 当前由 **静态硬编码路由** 兜住；`/news`、`/about/introduction` **完全没人接**。

### 3.3 静态路由 vs DynamicPage 共存策略建议

| 路径 | 建议短期方案（联调） | 建议长期方案 |
|------|---------------------|-------------|
| `/` | 保持 `views/home/Index.vue`（静态 sections）兜底；并行实现 `DynamicPage` 渲染 308 | 用 `DynamicPage` 接管，原 sections 作为 `component-map` 的目标组件 |
| `/news` | **优先解决**：在 `shouldRegisterDynamicRoute` 中放开 portal 注册 DynamicPage（成员 4 改），或成员 3 改 page.pageType=`custom` | DynamicPage 主，原 `news/CategoryList.vue` 等业务 view 作为 NodeRenderer 内的 component-map 目标 |
| `/services` | 保持静态 view；不与 DynamicPage 冲突 | 视产品决策：若需配置驱动则改走 DynamicPage |
| `/conference` | 保持静态 view（含子路由） | 同上 |
| `/about/introduction` | **同 `/news`**：放开 portal 或改 pageType | DynamicPage + `rich_text` 接 `AboutStaticArticle` |

**建议组合**：

1. 成员 4 在 `shouldRegisterDynamicRoute` 中，**当 `path` 不在硬编码静态路由集合内**（如 `/services`、`/conference`、`/login` 等）且 `pageType='portal'` 时，**也注册到 DynamicPage**；这样既不破坏现有静态页，又能接住 `/news`、`/about/introduction`。
2. 或者成员 3 把 `/news`、`/about/introduction` 的 `pageType` 调整为 `custom`（**不动 path**），让 `shouldRegisterDynamicRoute` 直接放行。

> 两种方案二选一即可；推荐 **方案 1（成员 4 侧改）**，避免动数据库。

## 5. YAAI API 风格与低代码接口接入建议

### 5.1 当前风格摘要

| 项 | 当前实现 |
|----|---------|
| **baseURL** | `import.meta.env.VITE_API_BASE_URL`（Vite 代理 `/api`） |
| **请求封装** | `src/utils/request.ts`（axios，10s timeout） |
| **响应 envelope** | 拦截器自动解：`success=true` → 直接返回 `Result<T>`（含 `success/data`）；`success=false` → ElMessage + reject |
| **camelCase / snake_case** | **camelCase**（前端类型、响应都 camelCase；与后端实测一致） |
| **列表字段** | `pages` 用 `data.records`、`menus` 用 `data.items` —— **后端约定不统一，store 各自处理** |
| **业务 API** | 已有 `news`、`banner`、`siteConfig`、`user`、`member` 等 |

### 5.2 建议新增 `public-node-tree.ts`

```ts
// 建议 - YAAI/src/api/public-node-tree.ts（成员4新增）
import request from '@/utils/request'
import type { Result } from '@/types/result'
import type { PageNodeTreeResult } from '@/types/lowcode'

export function fetchPageNodeTree(
  versionId: number
): Promise<Result<PageNodeTreeResult>> {
  return request.get(`/page-versions/${versionId}/node-tree`)
}
```

### 5.3 关于 `public-menu.ts` / `public-page.ts`

- `fetchMenus` / `fetchPages` 已在 `api/menu.ts` / `api/page.ts` 实现；**无需重复造**。
- 如需"前台 public"语义区分，可在同文件新增 `fetchPublicMenus()` / `fetchPublicPages()` 包装，约定 `status=true` 默认入参；当前 `fetchPages` 已支持 `{status:true}`。

### 5.4 建议新增 `types/lowcode.ts`

```ts
// 建议 - YAAI/src/types/lowcode.ts（成员4新增）
export interface PageNode {
  id: number
  pageVersionId: number
  parentId: number | null
  nodeType: 'container' | 'component' | string
  componentKey: string | null
  nodeName?: string | null
  slotName: string | null
  sortOrder: number | null
  dataBindingId: number | null
  propsJson: string | null
  styleJson: string | null
  layoutJson: string | null
  eventJson: string | null
  visibleRuleJson: string | null
  status: boolean
  // ...其它字段按需补
}

export interface PageVersionMeta {
  id: number
  pageId: number
  versionNo: number | null
  status: 'draft' | 'published' | string
  // ...
}

export interface PageNodeTreeResult {
  nodes: PageNode[]
  page_version?: PageVersionMeta  // 注意后端返回键为 snake_case
}

export interface PageNodeTreeNode extends PageNode {
  children: PageNodeTreeNode[]
}
```

> 注意后端返回字段中 `data.page_version` 为 **snake_case 键名**，但其内部字段仍 camelCase（见 `接口字段差异记录.md`）。

### 5.5 统一处理建议

| 项 | 建议 |
|----|------|
| **envelope** | 已有 `request.ts` 拦截器自动解，**沿用即可** |
| **`data.records` vs `data.items`** | 两者并存（不修改现有），新接口 `node-tree` 用 `data.nodes` |
| **camelCase** | 全 camelCase；类型层无需 snake_case 映射 |
| **`propsJson` 等字符串字段** | 运行时 `JSON.parse`，**try/catch** 兜底返回 `{}`；建议封装 `parseNodeJson(raw, fallback)` 工具 |
| **未知 `componentKey`** | `component-map.ts` 查不到时返回 `UnknownComponent.vue`（**不能** throw） |
| **错误兜底** | 拦截器已 ElMessage；NodeRenderer 内任何节点渲染异常应被 `<Suspense>` 或 `try` 捕获，**单节点失败不拖垮整页** |
