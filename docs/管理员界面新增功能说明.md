# 管理员界面新增功能说明

## 1. 本轮范围

- 成员3职责扩展到管理员后台前端页面实现（仍在 `yaai-lowcode` 项目内）。
- 本轮新增两个管理页面：
  - 会员审核
  - 会员订单查看

## 2. 会员审核页面

- 页面路由：`/member-audit`
- 使用真实后端接口：
  - `GET /member/audit/single/list`
  - `GET /member/audit/company/list`
  - `POST /member/audit/pass?memberId=xxx`
  - `POST /member/audit/reject?memberId=xxx`
- 页面支持：
  - 个人会员待审核列表
  - 单位会员待审核列表
  - 查看详情（对当前列表行做详情弹窗）
  - 审核通过/拒绝（带确认弹窗）

## 3. 会员订单查看页面

- 页面路由：`/member-orders`
- 页面命名为“会员订单查看”，不宣称完整“缴费管理”。
- 使用真实后端接口：
  - `GET /member/order/list?memberId=xxx`
  - `GET /member/order/detail?outTradeNo=xxx`
- 当前能力说明：
  - 仅支持按 `memberId` 查询订单
  - 不支持管理员全量分页
  - 不支持按状态、关键字、年份筛选

## 4. 接口限制与后续建议

- 订单接口当前限制：仅支持 `memberId` 条件查询，不支持管理员全量列表。
- 要实现完整缴费管理，建议后端补充最小接口：

`GET /member/admin/order/list`

建议参数：

- `current`
- `size`
- `keyword`
- `status`
- `year`

建议返回字段：

- `outTradeNo`
- `memberId`
- `memberNo`
- `memberName`
- `memberCategoryName`
- `amount`
- `status`
- `paymentMethod`
- `createdAt`
- `paidAt`
- `expireTime`

## 5. 不变更项

- 本轮不修改数据库。
- 本轮不修改后端代码。
- 本轮不影响现有低代码编辑器与既有模块。

## 6. 轮播图管理页面（新增）

- 页面路由：`/banner-management`
- 菜单名称：`轮播图管理`
- 目标：为管理员提供最简 Banner 数据维护能力（首页轮播图业务数据）。

### 6.1 使用接口

- `GET /banners`（列表，支持 `groupCode` / `status` 筛选）
- `GET /banners/active/{groupCode}`（查询生效轮播图）
- `GET /banners/{id}`（详情）
- `POST /banners`（新建）
- `PUT /banners/{id}`（更新）
- `DELETE /banners/{id}`（删除）

### 6.2 页面能力

- 筛选：`groupCode`（默认 `home_banner`）、`status`（全部/启用/停用）
- 表格：`id`、`title`、`groupCode`、`imageUrl`、`linkUrl`、`sortOrder`、`status`、`startTime`、`endTime`
- 操作：新增、编辑、删除（删除前二次确认）
- 表单字段：`title`、`subtitle`、`imageUrl`、`linkUrl`、`groupCode`、`sortOrder`、`status`、`startTime`、`endTime`、`remark`
- 仅做必填校验：`title`、`imageUrl`、`groupCode`
- 新增“预览生效轮播（只读）”区块，读取 `GET /banners/active/home_banner` 并展示图片/标题/副标题/链接/生效失效时间
- 预览为空时展示“暂无生效轮播图”
- 新增图片上传能力：上传成功后自动回填 `imageUrl`

### 6.3 与低代码页面节点关系

- 首页 `hero_banner` 在 `page_node` 中仅作为组件占位，不在 `propsJson` 中维护具体轮播图片。
- 轮播图真实数据来自 Banner 业务接口（`/banners` 与 `/banners/active/home_banner`）。
- 轮播图仍不存放在 `page_node.propsJson`。
- 首页 `HomeCarousel` 读取 `/banners/active/home_banner`。

### 6.4 图片上传接口状态（已实现）

- 上传接口：`POST /api/upload`（后端 `FileController`）
- 请求方式：`multipart/form-data`
- 表单字段：
  - `file`：文件本体
  - `type`：场景类型（当前使用 `other-attachment`）
- 返回：`Result<String>`，`data` 即图片 URL 字符串（可直接回填 `imageUrl`）
- 文件类型限制（后端）：`jpg/jpeg/png/gif/webp/pdf`
- 上传大小限制（后端）：`max-file-size=20MB`，`max-request-size=20MB`
- 页面侧前置限制（前端）：仅 `image/*` 且建议 `<=5MB`

### 6.5 上传请求收敛说明（本轮修复）

- 已将轮播图上传请求收敛到统一请求层：`src/api/http-client.ts`
- 新增统一 multipart 方法：`requestFormData(path, formData, options?)`
- `uploadBannerImage` 不再私有读取 `VITE_API_BASE_URL`，避免在业务 API 重复处理 baseURL/env
- 轮播图上传仍保持后端真实接口语义：`POST /api/upload`
- 在当前开发环境（`VITE_API_BASE_URL=/api` + Vite proxy rewrite）下，前端上传调用路径为 `/api/api/upload`，浏览器实际请求通过代理转发后命中后端 `/api/upload`

## 7. 新闻管理模块（新增）

- 页面路由：`/news`
- 目标：最简可交付新闻管理界面（列表 + 查询 + 新增 + 编辑 + 删除 + 详情）

### 7.1 使用接口

- `GET /news`（分页列表，支持 `current/size/categoryId/title/status/isTop`）
- `GET /news/{id}`（详情）
- `POST /news`（新增）
- `PUT /news/{id}`（编辑）
- `DELETE /news/{id}`（删除）

### 7.2 页面能力

- 查询：`title`、`categoryId`、`status`、`isTop`
- 表格列：`id/title/categoryId/publishTime/status/isTop/viewCount/author/source/summary`
- 操作：详情、编辑、删除
- 新增/编辑弹窗字段：
  - 必填：`categoryId`、`title`、`publishTime`
  - 可选：`summary`、`content`、`coverImage`、`source`、`author`、`status`、`isTop`、`remark`
- 详情弹窗：JSON 只读预览

## 8. 新闻分类管理模块（新增）

- 页面路由：`/news-categories`
- 目标：最简可交付新闻分类管理界面（列表 + 查询 + 新增 + 编辑 + 删除 + 详情）

### 8.1 使用接口

- `GET /news-categories`
- `GET /news-categories/{id}`
- `POST /news-categories`
- `PUT /news-categories/{id}`
- `DELETE /news-categories/{id}`

### 8.2 页面能力

- 查询：`name`、`code`、`status`
- 表格列：`id/name/code/parentId/sortOrder/status/remark/createdAt`
- 操作：详情、编辑、删除
- 新增/编辑弹窗字段：
  - 必填：`name`、`code`
  - 可选：`parentId`、`sortOrder`、`status`、`remark`
- 字段展示说明：`parentId` 在页面中显示为“所属菜单ID”（项目约定）

## 9. 操作日志管理模块（新增）

- 页面路由：`/log`
- 目标：最简可交付操作日志管理界面（列表 + 本地筛选 + 查看 JSON + 删除）

### 9.1 使用接口

- `GET /log/queryAll`（列表，不分页）
- `GET /log/queryById?id=...`（详情）
- `POST /log/delete?id=...`（删除）

### 9.2 页面能力

- 本地筛选：`tableName`、`operationType`、`operator`
- 本地分页：前端分页组件处理
- 表格列：`id/operationType/tableName/recordId/operator/operateTime/method/description`
- 操作：查看JSON、删除
- 详情弹窗：展示整条日志 JSON（含 `requestParams`、`newData`）
- 日志页不提供新增/编辑

## 10. 导航接入（新增）

- 侧边栏新增入口：
  - `新闻管理`
  - `新闻分类管理`
  - `操作日志管理`
- 工作台新增快捷入口：
  - `新闻管理`
  - `新闻分类管理`
  - `操作日志管理`

## 11. 限制与说明

- 本轮不改后端接口、不改数据库结构。
- 日志列表后端接口不分页，前端采用本地筛选和本地分页。
- `GET /news/{id}` 会触发浏览量更新，页面仅在“点击详情”时调用，避免列表批量调用。
