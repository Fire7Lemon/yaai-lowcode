## 2. 设计文件理解摘要

### 2.1 成员3的职责边界

- 输出**稳定的后台低代码数据与契约**：菜单、页面、页面版本、平铺节点树（page_node）、组件定义（component_def）、数据绑定（data_binding）。
- 维护后台低代码管理端前端（`yaai-lowcode/src`）：列表/表单 CRUD、低代码编辑器（节点树编辑、属性面板、保存）。
- 保持契约口径不动摇：响应 `{code, success, message, data}` + camelCase；前端 TS 类型/表单语义保持 snake_case；JSON 字段 `string | null`；camelCase↔snake_case 适配集中在 `src/api/*`。
- **不通过改后台数据绕过成员4缺失的运行时**；成员4缺什么由成员4补，成员3用 docs 指导。

### 2.2 低代码后台 ↔ 成员4前台对接链路

`GET /menus` → `GET /pages` → `route.path` 匹配 `page.path` → 读 `page.currentVersionId` → `GET /page-versions/{versionId}/node-tree`（camelCase 平铺 `data.nodes`）→ flat→tree（按 `parentId`/`slotName`/`sortOrder`）→ `NodeRenderer` 递归渲染 → 按 `componentKey` 查 `component-map`，未知键兜底 `UnknownComponent`；`propsJson/styleJson/layoutJson` 运行时 `JSON.parse` 并 try/catch 兜底。
