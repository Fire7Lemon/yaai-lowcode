## 1. 重置目标

- **当前目标**：在联调 / 测试场景下**清空已知错误的旧「页面链路」相关数据**，避免在错误 `path`、`currentVersionId`、 **`node-tree` 拓扑**、`componentKey` 上继续做增量修补。  
- **清空之后**：重建一套能够被 **成员 4 YAAI** 按既有契约消费的配置数据。**不修改 YAAI 仓库**。  
- **前台主要消费链路**（只读）：  
  1. **`GET /menus`** —— 导航与页面入口  
  2. **`GET /pages`**（及 **`GET /pages/{id}`** 等按需）—— 页面元信息与 **currentVersionId**  
  3. **`GET /page-versions/{versionId}/node-tree`** —— 页面节点树（平铺、`componentKey`、`propsJson` 等 camelCase 依后端实现）  

> 重建后的节点 **`component_key` / `componentKey`** 必须落在下文 **§3 白名单**；未知键仍以成员 4 兜底策略为准，但本方案的目标是**从一开始就避免未知键**。

## 2. 不再要求完整数据库备份的原因

| 考量 | 说明 |
|------|------|
| **数据性质** | 当前环境中的**页面链路数据**主要为联调 / 测试用途，且已认定为**系统性错误**，保留价值低于**干净重建**。 |
| **目标变化** | 目标从「修剪旧树」调整为**丢弃旧页面实例、按 YAAI 路由与白名单重写**；不要求在库内保留历史版本供业务回滚。 |
| **与「清空前快照」的关系** | **仍不做**「整库冷热备份等价物」作为强制前提；但必须做 **§4 清空前快照**：用于**审计谁被删了什么、比对是否清空干净、误删追责与复盘**，**不承诺**等价于一键整库恢复。 |

**风险提醒**：若在**同一实例**上还混有非页面类数据，快照应**明确列出涉及的 `page.id` / `versionId` / `menu.id`**，避免口头「全清空」误判范围。

## 3. 建议清空范围

### 建议清空 / 重建

下列实体上的**现存业务行**（联调库的「当前错误配置」），建议**整体删除后再按 §6 重建**：

| 模块 | 建议 | 主要原因（与现状盘点一致） |
|------|------|------------------------------|
| **menu** | 清空后重建 | 父级停用、 **`url_type=page` 与 externalUrl/query 混用** 等与 YAAI 不一致；宜按新导航骨架重做。 |
| **page** | 清空后重建 | 探针页、无效 `currentVersionId`、**`/about` 与前台子路由策略**等与目标架构不一致。 |
| **page_version** | 随 page 清空或显式删除 | 旧草稿与无效 **published/draft** 关系需废止。 |
| **page_node** | 先于或随版本删除 | 首页等问题：**componentKey 全空、多根**等，无法满足 YAAI 映射。 |
| **page_template** | 若为联调/错误基线则清空重建 | 避免新页仍「从污染模板分叉」；若有**已被认定为正式资产**的模板，改入 **§3 人工确认**。 |
| **reusable_fragment** | 若为联调占位则清空重建 | 同上；片段若与-footer/header 等新规范无关，应从零定义。 |

**概括原因**：

- 当前 **`path`、`page.current_version_id`、`node-tree`、`componentKey`** 与 **YAAI 已注册路由 + 冻结白名单** 不完全匹配。  
- **首页示例（version 101）**：全员 **`componentKey` 为空**、**多根并联**，**不适合作为前台消费数据**。  
- 旧 **模板 / 片段**若来自联调试错，**不宜**作为后续正式配置的默认基础。

### 建议保留

| 类别 | 说明 |
|------|------|
| **`component_def` 中白名单定义** | **原则上保留**（仅做缺失补齐、字段修正、非白名单项**停用**）；见下方白名单列表。 |
| **`data_binding` 中偏业务语义的数据** | **默认保留**；明显测试命名或无效的再单列删除（需人工确认）。 |
| **数据库结构（DDL）** | **保留**。 |
| **后端接口代码** | **保留**；不改变本方案文档职责范围。 |

**冻结白名单 `component_key`**（与白名单文档一致）：

- `page_container`  
- `hero_banner`  
- `notice_list`  
- `quick_links`  
- `home_services`  
- `home_events`  
- `news_list`  
- `home_shortcuts`  
- `friend_links`  
- `rich_text`  

### 需要人工确认后再处理

- **`component_def` 白名单外**但可能被旧对象引用的 **`container` / `hero_split_container` / `grid_container` / `nav_menu` / `copyright` / test_*`**：清空 **page_node** 后引用可能消失；仍需确认 **模板/片段内置树**是否引用。  
- **`data_binding`**：是否有关联 **CMS/API 正式配置**；仅当确认为联调占位再删。  
- **与新闻分类相关的**：若存在于 **CMS/独立表**，本方案默认**不属于**页面清空范围（见 §8）；低代码 **`menu`** 内用 query 顶替分类的职责应撤销并回归 **YAAI newsCategory API** 产品设计。  
- **任何不明显是测试数据、但被旧 page_node（或模板树）引用**的绑定或定义：**先快照再决策**，不单凭脚本删除。

## 4. 清空前快照

执行任意删除之前，必须把以下 **HTTP GET** 响应（可加 `--max-time 10`，直连 **`http://127.0.0.1:9876`**，**无 `/api`**）保存为：

- **只读存档**：团队知识库附件、工单、或 **`docs/` 外**受控目录中的 **`.json`**（避免把大图 JSON 常驻 git，除非合规允许）；或贴入经脱敏的内部 wiki。

**必拉取的接口清单**：

1. **`GET /pages`**  
2. **`GET /menus`**  
3. **`GET /component-defs`**（分页直至拉全）  
4. **`GET /data-bindings`**  
5. **`GET /page-templates`**  
6. **`GET /reusable-fragments`**  
7. **`GET /pages/{pageId}/versions`**（对**每一处将删除的 page**）  
8. **`GET /page-versions/{versionId}/node-tree`**（对**每一处将删除的 version**）

**快照用途**：

- **删除审计**：记录删前 **`id`、`code`、`path`、`currentVersionId`、菜单引用关系**。  
- **验证清空是否彻底**：清空后同名 GET 应符合 §9「清空后验证」。  
- **误删排查**：对照快照恢复逻辑关系（如需手动作业恢复个别行，也不在本文档范围内展开）。

可参考命令模板：[清洗前数据快照.md 附录 A](./清洗前数据快照.md)。

## 5. 推荐删除顺序

必须遵从**依赖自底向上**解除（无外键则说明以实际 DDL 为准，下列顺序供评审）：

1. **`page_node`**（挂于 `page_version`，最底层阻塞）  
2. **`page_version`**  
3. **`menu`**（若仍引用 **`page_id`**，宜在 **`page`** 之前有策略：或先清空 **`page_id`**，或后端允许悬空规则 —— **以实际 FK 为准**）  
4. **`page`**  
5. **`page_template` 自带 node-tree**（若后端将模板树独立于 page，则先删模板树下节点再走模板）  
6. **`page_template`**  
7. **`reusable_fragment` 自带 node-tree**  
8. **`reusable_fragment`**

**重要说明**：

- 若存在 **数据库级联删除**：可能通过删除 **`page` / `page_template` / `reusable_fragment` 父件**一并删除子行，**但必须用测试库先试一条链**验证，不可假设。  
- **若无级联**：必须严格执行 **先子后父**。  
- **不允许**先删 **`component_def` 白名单**（见 §8）。  
- **不允许**先清空 **`data_binding`**（除非你已确认全部为测试垃圾且成员 4 侧无契约依赖）。

## 6. 推荐重建顺序

清空（并验证 §9「清空后」）后，按下列顺序重建；均建议 **published 先行**，避免再次出现 **draft 当头版**。

1. **`component_def` 白名单确认**—— 缺则补录； **`test_*` / 非白名单** 按 §3 **停用或不建**。  
2. **`page`**（建议至少有如下 **`path`**，与 YAAI 常用路由对齐；名称/code 自定但需稳定）  
   - `/`  
   - `/news`  
   - `/services`  
   - `/conference`  
   - `/about/introduction`  
   - `/about/charter`  
   - `/about/regulations`  
   - `/about/leaders`  
   - `/about/branches`  
   - `/about/local`  

3. **`page_version`**  
   - **每个 page 至少保留一个 published 版本**  
   - **`page.current_version_id` 指向该 published 版本的 `id`**  

4. **`menu`**（骨架可与产品措辞微调）  
   - 首页 → `/` 对应 **`page`**  
   - **关于云智会** → 与子菜单 `/about/*` **`page`** 对应  
   - **服务矩阵** → `/services`  
   - **新闻动态** → `/news`（分类仍主要由 **YAAI newsCategory** 侧渲染，不把 query 塞进 **`menu.externalUrl`**）  
   - **会议系统** → `/conference`  

5. **首页 node-tree**（单根、`componentKey` ∈ 白名单），建议纵向顺序：

   - `page_container`（根）  
   - `hero_banner`  
   - `notice_list`  
   - `quick_links`  
   - `home_services`  
   - `home_events`  
   - `news_list`  
   - `home_shortcuts`  
   - `friend_links`  

   各块建议 **`propsJson`** 见：[后台API修正操作清单_待确认.md §5](./后台API修正操作清单_待确认.md)。

6. **关于 / 新闻 / 服务 / 会议页面 node-tree**  
   - 关于各子页：以 **`rich_text`**（或其它白名单允许的展示块）为主，避免再堆叠无键节点。  
   - 列表类页：`**news_list` + 绑定**，与 **`data_binding`**、CMS 对齐。  

**整树 `PUT`** 仍以 [首页节点树重建方案_待确认.md](./首页节点树重建方案_待确认.md) 风险管理：优先编辑器 / 分步 API。

## 7. 推荐执行方式

### 方案 A：优先后台 API / 管理端删除与重建

| 优点 | 缺点 |
|------|------|
| 更符合业务语义与校验链 | **周期较长**，依赖 UI/API 完备 |
| 易暴露权限、版本、发布校验问题 | 需人工逐步点选或脚本化 **只读**清单辅助 |

### 方案 B：由后端执行受控清空脚本（仅测试库）

| 优点 | 缺点 |
|------|------|
| **见效快**，适合联调库整体重置 | 必须厘清 **FK、级联、软删除** |
| 可配合「只删页面域表」 | 易误伤若范围未与 §3 对齐 |

**建议**：若目标为**彻底重置联调库页面域**，可在 **§4 快照 + §3 签字** 后，由 **DBA/后端**在**测试库**执行脚本；**生产环境**不适用本方案的「弱备份」基调，除非单独评审。

## 8. 禁止清空项

执行任何删除时必须遵守：

| 禁止 | 说明 |
|------|------|
| 不清空白名单 **`component_def`** | 可增补、可调字段，不得以「重置」为名删光再不知能否恢复 DDL 种子以外的业务定义 |
| **默认不清空 `data_binding`** | 除非你方已确认为测试占位且 YAAI/CMS 无异议 |
| 不清空 **用户 / 权限 / 系统配置** | 不属于本「页面链路」重置范围 |
| 不清空 **新闻正文、栏目、banner 内容、分类主数据**等业务表（若独立于低代码 **`page`**） | **YAAI 运行时内容**不因低代码清空而删库 |
| **不修改 YAAI** | 成员 3/后端输出对齐白名单与路由 |

## 9. 执行后验证

### 清空后（定性）

- **`GET /pages`**：**无旧 id** 或为**空白**（与执行范围一致）；不应再出现已知探针 path。  
- **`GET /menus`**：**空**或与「已删菜单」清单一致。  
- **旧 `GET /page-versions/{oldVersionId}/node-tree`**：**404 / 不再 success**（或后端约定等价「无节点」且不用于前台）。  
- **`GET /component-defs`**：**白名单行仍在**。  
- **`GET /data-bindings`**：**与快照对比为保留**：条数不降除非已签字删测试绑定。  

### 重建后（定性）

- **`GET /menus`**：可生成与设计一致的导航树；**`page` 类型指向正确 `page_id`**。  
- **`GET /pages`**：可按 **`path`** 找到上述 §6 所列页面；**无 draft 当头版**。  
- **`GET /page-versions/{versionId}/node-tree`**：  
  - **首页**：**唯一根 `page_container`**，`componentKey` **均在白名单**、**非空**（业务叶子），**parentId** 拓扑不断链  
  - 其他栏目页：**可渲染**，键名合规
