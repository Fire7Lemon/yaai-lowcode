# 首页节点树重建方案（待确认 · version **101**）

> **不写库、不提供可一键执行的破坏性 PUT**。  
> 背景数据见：[清洗前数据快照.md §8](./清洗前数据快照.md)、[后台API修正操作清单_待确认.md §5](./后台API修正操作清单_待确认.md)。

---

## 1. 为什么**不**附带「可复制执行」的 `PUT …/node-tree` JSON

1. **`PUT /page-versions/{id}/node-tree` 的契约细节**在不同后端版本上对以下行为未必一致：**新建节点时的 `id`（null vs 负数 vs 占位）**、`parentId` **如何引用新建子节点**、以及 **服务端是否重写 `sortOrder`/槽位**。在未拿到**后端书面确认**之前，贸然用虚构 id 容易造成 **父子关系丢失或多根**，与已知「整树 PUT 破坏结构」类风险叠加（参见 [接口字段差异记录](../01_设计基线/接口字段差异记录.md)、[后端待修复清单](../04_后端修复/后端待修复清单.md) 中相关问题）。  
2. **JSON 标准无注释**：若请求体中含大量「伪 id」，读者易误拷贝进生产。**安全默认**是：**后台低代码编辑器**或 **分段创建接口**生成真实 id。

---

## 2. 推荐落地方式（按优先级）

| 优先级 | 方式 | 说明 |
|--------|------|------|
| **P0** | **后台页面编辑器** | 清空或重建：**单根 `page_container`** → 按顺序挂载白名单组件 → **逐节点**填 `propsJson`（或服务端默认）；**拖拽 / move** 解决 `slotName`。 |
| **P1** | **API 分步创建节点**（若后端提供 **`POST`** 创建 page_node **而非**单次整树覆盖） | 每步 **`GET node-tree`** 校验 **真实 `id`** 再添加子节点 → 降低一步 PUT 翻车面。 |
| **P2** | **`PUT /page-versions/101/node-tree`** | **仅在**：① 后端确认 **camelCase `nodes`** 载荷；② 确认 **新客户点 `id: null`** 或服务端分配的临时 id 规则；③ **在测试版本 id 上演练成功** —— 再在联调库执行。载荷占位见 **[首页节点树重建请求体_待确认.json](./首页节点树重建请求体_待确认.json)**（**仅占位**，**禁止未评审直 PUT**）。 |
| ✗ | **SQL 批量改 `page_node`** | **不推荐**：JSON 转义、`slot_name`、`depth`、审计字段极易与运行时 API 不一致。 |

## 3. 目标结构（拓扑 · 与白名单对齐）

详见 [后台API修正操作清单 §5](./后台API修正操作清单_待确认.md)：根 **`page_container`**，子序列 **`hero_banner` → `notice_list` → `quick_links` → `home_services` → `home_events` → `news_list` → `home_shortcuts` → `friend_links`**。

**`propsJson`** 字符串建议值已写在操作清单 **§5**，此处不重复以避免双处漂移。

---

## 4. 数据绑定建议（可选 · 不改变表结构前提下）

在完成 **component_def** 与白名单对齐后：

- **`hero_banner`**：可 **`dataBindingId`** 指向现有 **banner** 绑定（若节点模型支持）；否则纯 props 占位。  
- **`notice_list` / `news_list`**：同理引用 **`data_bindings`** 中 article/banner 类绑定（以 **GET /data-bindings** 为准）。

实施前用 **GET** 核对绑定 **id** 仍存在。

## 5. 验证

```bash
curl.exe --max-time 10 -sS "http://127.0.0.1:9876/page-versions/101/node-tree"
```

期望（定性）：

- **唯一根** `page_container`（`parentId` 语义以响应为准：`null` 或约定根）。  
- 所有业务节点 **`componentKey`** 为非空且 ∈ 白名单。  
- **`propsJson`**/`props_json`（视响应 casing）可被成员 4 解析。
